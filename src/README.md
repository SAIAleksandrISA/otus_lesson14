# Очередь данных для работы по схеме Producer-Consumer

Данный проект представляет собой реализацию очереди данных для работы по схеме Producer-Consumer на C++. Проект разработан с учетом требований к многопоточности, производительности и гибкости архитектуры.

## Соответствие требованиям проекта (ФТ/НФТ)

| Требование | Описание реализации | Способ верификации |
| :--- | :--- | :--- |
| **Хранение данных любого типа** | Использование C++ шаблонов `template <typename T>`. | `safequeue.hpp`, `safepriorityqueue.hpp` |
| **Потокобезопасность** | Защита данных через `std::mutex`, `std::unique_lock`, `std::atomic`. | `stress_test.cpp`, `test_concurrency.cpp` |
| **Многопоточные режимы (Multi-P/Multi-C)** | Архитектура поддерживает N продюсеров и M потребителей. | `main.cpp` |
| **Приоритезация данных** | Реализация `SafePriorityQueue` на базе `std::vector` + heap-алгоритмы. | `test_priority_logic.cpp` |
| **Тестирование** | Набор юнит-тестов и стресс-тест производительности. | `test_priority_logic` `stress_test` `test_concurrency`|

---

## Архитектурные решения

### 1. Потокобезопасность
Все критические секции защищены мьютексами. Для уведомления потребителей используется `std::condition_variable`, что позволяет избежать «активного ожидания» (busy waiting) и снизить нагрузку на процессор.

### 2. Поддержка Multi-Producer / Multi-Consumer
Проект позволяет гибко настраивать количество потоков-продюсеров и потоков-потребителей. Основной поток (main) управляет жизненным циклом, гарантируя корректное завершение работы (`graceful shutdown`) с помощью `join()` всех потоков.

### 3. Приоритетная очередь
В отличие от стандартной очереди, `SafePriorityQueue` обеспечивает извлечение элементов согласно их приоритету. Вместо использования `std::priority_queue` с небезопасным `const_cast`, реализован прямой доступ через `std::vector` с использованием функций `std::push_heap` и `std::pop_heap`. Это гарантирует корректную работу с данными без лишних копирований.
